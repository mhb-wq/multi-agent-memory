历史成绩为历史自动裁判结果，仅作同题参考。完整基线答案和裁判按检查点保存在 historical_baselines.jsonl，来源文件及 SHA-256 记录于 selection.json。历史基线使用 deepseek-flash 旧服务；在线模型别名随时间可能变动，推理模式和各配置可能不同，不声称严格同模型配对。

运行两组：full（当前代码、立即联合维护、状态独立检索）和 cards_only（关闭状态维护、状态读取及 Sleep）；两组分开建库，均用 deepseek-flash、禁用 thinking、本地 all-MiniLM-L6-v2、官方 query prompt 和官方 LLM judge。此设置同时改变状态维护和读取，不是仅隐藏状态文本的单因素消融；独立抽取存在模型波动。

依照官方检查点按 turn 增量处理，不传入未来对话；模型按官方提示选择 action，隐藏标准答案和评分字段。按照官方所有检查点回放，但是共享池不提供完整访问控制和结构化删除，因此隐私和删除方面的结果只展示系统行为，不能宣称治理能力。评估状态、遗漏和 token 单独记录。

预算代理以模型返回 usage 累计，上限约 600 万 token 且留 5 万余量（用户 2026-11-18 确定；已启动进程保守上限为 300 万，下一进程起生效 600 万）。账本含先前连接/试运行用量，以及四次传输异常但是否计费未知的共 20 万 token 保守预留；这不是账单。此前试运行单独保存，不计入实验对比。超时、缺失 usage 或超预算暂停后续调用。临时直连结构化测试另有 487 token，测试时间及实际账单以服务端为准。

已启用断点恢复：跳过已接收并保存的历史消息和已完成的检查点回答；只对末尾处理未完成的消息重新尝试，后续继续增量回放。恢复实现属于运行过程调整，日志保留。

## 2026-11-18 用户调整：并行与预算

用户明确取消 token 上限，并要求教育场景并发启动。e16 完整组和仅卡片组分别使用独立进程、独立代理端口和用量账本运行。e03 旧进程沿用原有 600 万阈值，监督程序等待旧进程退出，若未完成则在保留旧答案与断点的基础上按无上限配置继续。网络传输异常时监督程序有限次数自动重试，无法获取 usage 时仍暂停以保留可审计性；并发可能影响延迟，不将运行耗时直接当作公平对比。
