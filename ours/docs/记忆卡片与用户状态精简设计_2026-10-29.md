# 多用户共享记忆：卡片与用户状态精简设计

## 研究重点

一个公共记忆池同时服务多个用户。卡片负责保留对话中值得记住的事实、事实归属及可核验的原文，附带一句可修正的基本使用提示；State 负责表示某个用户某个事项的当前值、历史及不确定性；Sleep 根据新的卡片维护状态。回答时结合问题、检索到的卡片和相关 State 判断当前该如何使用，而不是把提示本身当作事实。没有权限控制作为研究目标。

## 两篇论文与本设计的区别

- DG-Mem（用户提供的 ICLR 2027 匿名审稿稿）以消息为证据，建立内容图和用户上下文图，利用说话人、回复关系和时间连接共享历史，按提问人和问题选取证据。它并不是给抽取卡片写使用说明，也不是我们已实现的方案。启发：公共记忆仍需保留作者及消息关联，提问人与事实主体不必相同。
- EvoMemState（用户提供的匿名 ACL 投稿稿）组织有来源、时间及更新/冲突关系的记忆，针对查询合成相关用户状态，并用经 GRPO 训练的策略生成动态使用规则。论文在其设置中报告固定通用指导不稳定。我们的 use_hint 是抽取时生成的未训练基础提示；查询时的 usage_note 才结合当前问题与可见状态，不能称为复现其 RL 策略或其查询时状态合成。

## 概念层的最小结构

卡片：`内容`、`归属主体`、`来源（说话人+原文）`、`基本使用提示`、必要的 `时间/限定`；内容可能属于个人，也可能是没有个人归属的公共事实或主体未确定的事实。不能把动作执行者等同于事实所属者。

例：

```
内容：Asha 的 EEG 预约改到周五下午两点。
主体：Asha
来源：Noah 的原话 + 归属所需前文
基本提示：可用于回答 EEG 预约时间；需留意后续更改。
```

这条提示不是确认事实的证据，不保证模型生成正确；回答时仍应结合实际问题、原文、时间和 State。用户说“计划改期”应保持计划属性，不能改成已经完成。

用户 State：`主体`、`事项`、`值`、`状态（确定/待确认/冲突/未知）`、必要的 `时间` 和 `支持证据`。同一个人可以有多个事项，同一事项可以保留旧值、新值或冲突。系统内部将一个事项存为带 assertions 的记录；模型可见精简状态是这些关键内容的视图，不是宣称底层已变成单条覆盖式值。

## ID 和证据是什么

`item_id` 是可选事项标识，用来区分或关联事项，且当前某些导入会让它参与 State 地址；不是原文或记忆值。它不能单独代替对话归属理解。`source_message_id` 指来源消息，支持定位原文和关联同消息卡片；`source_event_ids` 指系统处理事件，支持 Sleep 回到证据；`source_root_ids` 表示来源链的根，用于区分重复转述与独立证据、保留来源。它们不需要成为卡片正文，但目前与去重、State 状态、历史记录、旧实验和数据恢复有依赖，因此没有物理删除，也不能随意把这些 ID 合并。后续若取消来源链功能，应通过迁移和受控验证再调整。

`evidence_kind` 是这条事实的**来源表达性质**：例如用户明确陈述、转述、计划或工具结果，是系统判断证据如何支持状态时的辅助依据。例如“我计划周五出发”不是“我周五已经出发”。类型本身不是该事实正确的证明，也不是权限标签。当前规则将不同来源用于确定或待确认，错误标注仍会污染状态。

## 本次具体代码改动

1. 直接抽取的模型输出精简为主体、类别、内容、原文、证据类型、`use_hint`、最小 State 映射（`state_key`、`state_aspect`、`value`）和主体分析/前文依据。事件时间、有效时间、单位、条件、事项更正等在有证据时才选填。程序生成必要的内部标识与存储字段；接受旧格式以兼容测试和重试。
2. 写入时将 `use_hint` 随卡保存，放入读取时的卡片视图和说明生成输入；它不作为 State 更新或主体确认的证据。答题时仅在既有词面依据检查通过的情况下进入最终 usage_note；具体使用说明仍由当次查询生成，不通过则忽略。该词面检查不是语义验证，可能过滤有用提示，也可能放过不合适的提示。
3. `semantic_views.py` 提供精简卡片与 State 投影：在共享池模式下，仅将语义必需字段及引用卡片 ID 提供给说明模型和 State/Sleep 模型；不在这些提示中携带 policy、权限列表、源事件 ID 等内部字段。主体前文引用保留在模型视图中。旧完整记录仍用于代码校验、状态事务和追溯，没有破坏现存文件，也没有删除历史实验。
4. 没有改变单一公共库、查询 top-k、Sleep 触发频率或现有 State 地址算法。没有实现 DG-Mem 双图、EvoMemState 的 ontology/强化学习，也没有解决模型主体归属或说明效果问题。

## 验证与后续

本次离线针对性测试覆盖精简输入、跨用户公共池、Sleep、旧格式兼容及静态提示写入；未调用真实模型或重跑数据集。须在新运行目录分别对照同一批卡片/同一 State：无说明、仅静态 use_hint、动态说明、两者结合，评估回答质量、更新/冲突识别、错误归属、说明正确性和成本。相同候选与回答配置才能隔离说明的作用。

暂未物理删除内部 ID、历史权限字段、State 的 assertions 或旧索引。此为兼容性边界，不是说这些字段都应显示给产品用户，也不是声称实体模型已经完全精简。删除或重设它们需迁移工具与新旧数据一致性验证，避免破坏历史结果。
