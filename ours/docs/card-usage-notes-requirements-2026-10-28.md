# 卡片使用说明：已确认的实现要求

状态：使用说明设计已部分实现；不修改已完成实验的结果。

1. 在现有权限检查之后，筛选 LLM 结合当前问题、候选卡片和允许内部筛选使用的、可核对的用户状态，判断相关性。普通卡片和状态相关卡片都应判断与问题是否相关。
2. 对被选中的状态相关卡片，LLM 根据卡片证据和状态，为当前问题自行撰写具体使用意见，而不是只能从预设用途标签或固定句子中选择。意见应帮助理解可用事实、当前/历史关系、适用条件、冲突或不确定性，按现有证据表达，不得虚构主体、适用对象、授权或状态。
   输出结构固定为 `{"card_ids":["card_1"],"uses":{"card_1":"模型自行撰写的使用说明"}}`；每张选中卡对应一条说明，字段名和映射结构固定，说明的文字内容不预设。
3. 普通卡片可给简短用途说明，不应假称由用户状态支持或包装成状态卡。意见应适度具体，长度设置有界并在测试后调整，避免淹没证据；不能简单把说明越写越长当作改进。
4. 状态尚未整理，不等于原话必然错误或不可使用。说明应提示结合原话、时间和其他证据判断，不能一律要求拒答或丢弃证据。
5. 用户状态属于内部筛选信息；交给回答 Agent 的是卡片和经检查的使用意见，不直接提供完整状态。意见本身不得暴露接收者无权查看的信息；状态依赖的权限不可从说明中绕过。无法安全确认时不生成敏感说明。
6. 程序验证输出结构、卡片 ID、说明归属、类型和长度等可确定的规则，并保留原始证据和筛选诊断；格式校验不等于证明意见的语义正确。JSON无法解析或结构不符时，把具体格式错误反馈给模型并重试一次；仍失败则按原排序把真实候选卡片交给回答模型，不附任何使用说明，记录降级。非格式的网络、账户和服务故障不伪装成格式降级。
7. 对照实验：同一问题、同一证据、同一回答模型和官方问答模板，比较旧说明、无说明、新说明；该对照仅用于诊断，不替代原实验成绩，不使用标准答案指导生成说明。

后续用户更改：本轮共享池模式只使用当前消息生成卡片，不使用此前讨论的前文；上下文能力保留供其他模式使用。每处理 20 条消息触发一次 Sleep，不因单道问题额外触发；Sleep 是受信任的内部维护过程，可读取负责空间内相关卡片。共享池模式本轮不启用用户或 Agent 访问权限过滤；受治理模式仍保留权限检查。参见 `shared-pool-mode-2026-10-28.md`。
