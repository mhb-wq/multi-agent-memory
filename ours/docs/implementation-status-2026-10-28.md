# 2026-10-28 权限、卡片和 Sleep 改动状态

本次只修改代码与运行本地模拟测试，未重跑任何数据集或调用付费模型；原有实验产物保持原样。

- 直接卡片提取可接收最多10条、6000字符的此前消息并记录上下文候选消息ID；GateMem、GroupMemBench及使用其回放器的PERMA诊断路径接入。上下文ID只记录候选来源，并不证明模型用了哪条，也尚未形成可级联删除的完整来源图。
- GateMem、GroupMemBench和PERMA诊断回放按每20条消息触发内部Sleep；GroupMemBench主回放亦改为该规则。未满20条不在答题前额外维护。受信任维护者可处理本空间各主体的待处理卡，不改变对外读取权限；普通调用者原有授权检查保留。
- 筛选提示词要求针对每张选中卡自由写简短使用意见；程序校验卡片ID、长度和词面依据，无法证明说明的语义和权限正确。无法通过保守校验时省略自由意见并保留通用提示。状态未维护不等于事实错误。
- GateMem范围细分：预约、到达、停车、路线、其他物流、临床、联系、项目排期、预算和其他业务。只对明确可解释的有限结构化关系初始化相应读取规则；目前仅覆盖部分显式范围和预算负责人关系，并不代表所有场景关系都已支持。
- GateMem对两种严格形式的明确授权/撤权可经程序核验后执行，其他自然语言控制意图仍会记为待确认；部分删除和传播副本的清理没有实现完整的自动验证。不能将其说成全场景完整权限链路。
- 通用 `MultiUserMemory.configure_control_recognition` 路径对不明确或未完成控制操作仍会抛出验证错误；GateMem 适配器的待确认不中断策略尚未推广到该通用路径。
- GroupMemBench现有回放配置仍有默认团队成员间广泛读取授权，尚未完成逐范围的可信授权初始化；已移除跨主体自动确认权限。也未验证PERMA和GroupMemBench的所有入口都使用同一控制配置。不能把这两条路径称为权限边界已完成。
- 本地测试：88项通过，1项 FastAPI TestClient 测试挂起后未包含在本次通过结果中。未做真实数据端到端或付费模型测试，模型抽取、分类、授权范围映射、说明语义以及性能均未得到端到端验证。
